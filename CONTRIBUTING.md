# Contributing

Contributions are welcome when they improve the project and remain aligned with its purpose.

## Before Contributing

1. Check existing issues and pull requests.
2. Avoid duplicating an existing contribution.
3. For significant changes, open an issue first to discuss the proposed approach.

## Development

Keep changes focused and easy to review.

When submitting code:

- Use clear naming.
- Keep the implementation simple and maintainable.
- Avoid unrelated changes.
- Test the affected functionality before submitting.
- Do not commit secrets, credentials, API keys, or private data.

## Pull Requests

A pull request should contain:

- A clear description of the change.
- The reason for the change.
- Relevant screenshots or output for UI changes.
- Testing information when applicable.

Keep commits and pull requests focused on one logical change where possible.

## Issues

When opening an issue, include:

- A clear title.
- A description of the problem or requested improvement.
- Steps to reproduce bugs.
- Expected and actual behavior.
- Relevant environment information.

## Code of Conduct

By contributing, you agree to follow the project's [Code of Conduct](CODE_OF_CONDUCT.md).

## Security

Do not report security vulnerabilities through public issues. Follow the process described in [SECURITY.md](SECURITY.md).
